The problem

A citation is the beginning of a review.

Technical documents evolve. Finding a relevant paragraph does not establish which requirement changed, whether two quantities mean the same thing, or who accepted a finding. AEGIS joins those steps in one inspectable workflow.

01 / RESEARCH

Answers with inspectable evidence

BM25 and local semantic retrieval feed bounded investigations. Accepted claims retain source identities and exact quotations; unsupported questions can return insufficient evidence.

02 / COMPARE

Requirements across revisions

Enumerate explicit requirements, match stable IDs, show additions and removals, and compare supported units and limits with conservative context checks.

03 / REVIEW

A durable human decision

Inspect both quotations, accept, reject or request follow-up, then export the findings and decision history. Ambiguous identity and unsupported expressions remain visible for review.

Recorded application · Synthetic documents

From two specifications to a reviewed change.

  1. Upload revisions A and B. The invented controller's maximum operating temperature changes from 85°C to 80°C.
  2. Open Revision review. The stable requirement ID matches both quotations. With unchanged subject, modality and conditions, the lower maximum is a tighter limit.
  3. Record a decision. Save a review note and export the matrix. The recorded decision is separate from a generated answer.
  4. Investigate and inspect citations. The actual pinned local model compares the revisions. Open the exact quotation, source hash and ranges; follow-ups retrieve evidence again.

The recording includes real generation waits and browser checks. It has explanatory captions rather than an audio narration. Test accounts exist only in the temporary demonstration workspace.

One host · Bounded workers · Shared provenance

A modular monolith that fits the hardware.

Browser + private sessionsFastAPI + SQLiteIsolated parsing + OCRSource-mapped chunksBM25 + BGE vectorsLocal Qwen3 8BQuote checks + review matrix

One quantized inference model runs on an 8 GiB GPU, with CPU embeddings and bounded queues. Code owns authorization, numerical comparisons and quotation validation. The model proposes answers; a separate support review remains fallible. Source hashes and pipeline versions identify saved results.

The native Linux deployment uses separate app and inference service accounts behind a TLS proxy, with a private model listener, readiness checks and offline verified backup/restore. SQLite and exact vector search target a single instance.

Measured checks · Explicit limits

Evidence for the implementation.

Real browser workflows

Private login, PDF/DOCX and OCR, two-account isolation, saved research, exact source inspection, unsupported-question abstention, cancellation and review/export passed local Chrome checks.

Recovery over HTTPS

A real local Caddy proxy verified secure login cookies, restart persistence and backup recovery. Restoring revokes old sessions. Public DNS and certificate issuance require a hosting target.

Controlled retrieval study

On eight synthetic English paraphrases, dense and hybrid retrieval both reached recall@3 of 1.0; dense ranked first more often. This is a development smoke set, not a held-out benchmark or proof of general superiority.

Boundaries: explicit English requirements and supported single-bound quantities; compound formulas, implicit requirements and ambiguous matches need manual review. Bounded retrieval is not exhaustive document understanding. Reference validity is not proof of semantic correctness. This project has no defence certification or claimed organizational deployment.
